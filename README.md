# Classroom Behaviour Detection Using YOLO12m

A computer vision project for detecting and tracking student behaviours in classroom videos using **YOLO12m** and **ByteTrack**.

The goal is to identify observable classroom activities from video frames, such as working, standing, phone use, sleeping, bowed-down posture, and non-attentive behaviour.

## Project Overview

This project uses a custom annotated classroom dataset to train an object-detection model from scratch.

The workflow includes:

- Creating and annotating a classroom behaviour dataset
- Augmenting training images
- Training a YOLO12m model from scratch
- Evaluating precision, recall, and mAP metrics
- Running detection on classroom videos
- Using ByteTrack to assign persistent IDs across video frames

## Behaviour Classes

| ID | Class | Description |
|---:|---|---|
| 0 | `bowed_down` | Student has their head bowed down |
| 1 | `non_attentive` | Student appears not to be attentive |
| 2 | `sleeping` | Student appears to be sleeping |
| 3 | `standing` | Student is standing |
| 4 | `watching_phone` | Student is using or viewing a phone |
| 5 | `working` | Student is engaged in classwork |

## Dataset

The dataset contains approximately **190 original classroom images**.

Data augmentation was applied to expand the training material to approximately **470 images**.

The dataset uses YOLO detection format:

```text
dataset/
├── train/
│   ├── images/
│   └── labels/
├── valid/
│   ├── images/
│   └── labels/
├── test/
│   ├── images/
│   └── labels/
└── data.yaml
```

Each annotation file contains normalized bounding-box values:

```text
class_id x_center y_center width height
```

## Model Training

The model was trained from scratch using the YOLO12m architecture.

| Setting | Value |
|---|---|
| Model | YOLO12m |
| Training method | From scratch |
| Configuration | `yolo12m.yaml` |
| Image size | 1280  |
| Optimizer | AdamW |
| Epochs | 300 |
| Batch size | 2 |
| Video tracker | ByteTrack |

```python
from ultralytics import YOLO

model = YOLO("yolo12m.yaml")

results = model.train(
    data="data.yaml",
    pretrained=False,
    epochs=300,
    imgsz=640,
    batch=2,
    device=0,
    optimizer="AdamW",
)
```

## Evaluation

The model was evaluated using:

- Precision
- Recall
- mAP@50
- mAP@50–95

```python
metrics = model.val(
    data="data.yaml",
    split="val",
    imgsz=640,
    device=0,
    plots=True,
)

print(f"Precision: {metrics.box.mp:.4f}")
print(f"Recall: {metrics.box.mr:.4f}")
print(f"mAP50: {metrics.box.map50:.4f}")
print(f"mAP50-95: {metrics.box.map:.4f}")
```

### Observations

- `standing` achieved the strongest class-wise result, with **92.3% mAP@50**.
- `bowed_down` achieved **73.0% mAP@50**.
- `watching_phone` achieved **71.7% mAP@50**.
- The validation data was imbalanced: it contained approximately **592 `working` instances** but only **4 `sleeping` instances**.
- The validation set contained only **29 images**, so results should be interpreted carefully.

## Video Tracking

ByteTrack is used to maintain student IDs across video frames.

```python
from ultralytics import YOLO

model = YOLO("classroom_yolo12m_v2.pt")

for _ in model.track(
    source="classroom_video.mp4",
    tracker="bytetrack.yaml",
    conf=0.35,
    imgsz=1280,
    persist=True,
    stream=True,
    save=True,
):
    pass
```

`stream=True` processes one frame at a time and helps prevent memory issues when processing longer videos.

## Limitations

- The original dataset is relatively small.
- Data augmentation increases image count but does not replace diverse real classroom data.
- Some classes have far fewer examples than others.
- Occlusion, lighting changes, camera angles, distance, and student position can reduce detection quality.
- Phone detection is difficult when phones are small, hidden, or far from the camera.
- Predictions should be reviewed by people and should not be used as the sole basis for decisions about students.
